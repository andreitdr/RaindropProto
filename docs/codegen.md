# Code generation

No generated code is kept in this folder. Each consumer generates its own.

## Server (C#)

`RaindropServer/RaindropServer.Grpc` compiles every `raindrop/v1/*.proto` with the `Grpc.Tools` NuGet
package, which ships its own `protoc` and C# gRPC plugin:

- `GrpcServices="Server"`, into namespace `RaindropServer.Grpc.Protocol`.
- It runs on every `dotnet build`, so there is nothing to run by hand and nothing generated is committed.
- `google.rpc.Status` and `ErrorInfo` come from the `Google.Api.CommonProtos` package (the error
  trailer, see [errors.md](errors.md)).

## Client (Dart)

`RaindropClient/tool/gen_protos.sh` runs `protoc` with the Dart plugin into
`RaindropClient/lib/core/network/grpc/generated/`. It generates:
- `raindrop/v1/*.proto`
- the well-known types it uses (`timestamp`, `duration`)
- `google/rpc/status.proto` and `google/rpc/error_details.proto`, for decoding the error trailer

The output **is committed**, so `flutter run` needs no code-generation step, like the rest of the
client. Rerun the script after any change here.

Requirements:
- `protoc` (`brew install protobuf`).
- The Dart plugin: `dart pub global activate protoc_plugin`, with `~/.pub-cache/bin` on `PATH`.

Versions that must agree:

| Piece | Version | Why |
|---|---|---|
| `protoc_plugin` | 25.x | generates code for the `protobuf` 6 runtime |
| `protobuf` (Dart runtime) | 6.x | already pinned by `livekit_client`; the generated code and LiveKit share it |
| `grpc` (Dart) | 5.x | works with `protobuf` 6 |

These were checked together: code generated by `protoc_plugin` 25.1.0 analyzes cleanly against
`protobuf` 6.1.0 and `grpc` 5.1.0.

## Linting

`buf lint` uses the STANDARD and COMMENTS rule sets, excluding per-field and per-enum-value comments.
`buf format -w` keeps formatting stable. `buf breaking` uses WIRE rules (see
[conventions.md](conventions.md#evolving-the-schema)).
